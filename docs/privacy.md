# Privacy

Personal data the app stores, where it lives, and how long. Every new data processor needs an entry here (AGENTS.md).

## Processors

| Processor | Region | Data |
|---|---|---|
| Supabase (Postgres, Auth, Storage) | Frankfurt (hosted projects `nblm-develop` and later production) | Accounts, notebooks, memberships, membership audit, sources, chunks with embeddings, chat messages, model usage |
| AWS Bedrock (Titan Text Embeddings V2) | EU only: before every call the code checks `BEDROCK_REGION` against an EU allowlist (eu-central-1, eu-north-1, eu-west-1, eu-west-3, eu-south-1, eu-south-2); configured as eu-central-1 with the on-demand model id, no inference profile (configuration, not checked in code). The region SCP blocks Bedrock outside these regions | Source chunk text, sent to compute embeddings. Bedrock does not store or log inputs and outputs and does not use them for training ([Bedrock data protection](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html)). Bedrock model invocation logging must stay off; no stack configures it (`infra/aws` from PR #29 does not), not verified in the account from the sandbox. The app logs no source text (AGENTS.md) |
| AWS Bedrock (Amazon Nova 2 Lite, chat) | EU only: called in eu-central-1 through the EU system inference profile `eu.amazon.nova-2-lite-v1:0`, which routes requests to eu-central-1, eu-west-1, eu-west-3, eu-north-1, eu-south-1 or eu-south-2 (read with `get-inference-profile` on 2026-10-19); the web roles' IAM policy allows only this profile and these regions, and the region guard SCP blocks Bedrock elsewhere | The user's question and the retrieved chunk text of that notebook, sent to generate the answer (block D); the answer comes back. Bedrock does not store or log inputs and outputs and does not use them for training ([Bedrock data protection](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html)); invocation logging stays off. The app logs no question, source or answer text (AGENTS.md) |
| Vercel (functions, hosting) | Functions in `fra1` (`apps/web/vercel.json`); the CDN serves from the nearest edge. Builds run on Vercel's build infrastructure, region not verified; builds handle no personal data | Every request (IP address, paths, session cookies) and the responses rendered from the data above. Projects `nblm-web-develop` (develop, live demo) and `nblm-web` (production) |
| GitHub (OAuth identity provider) | GitHub, outside the EU | On GitHub login: GitHub learns that the user signs in to the app; the app receives the GitHub user id, name, avatar URL and email from GitHub through Supabase Auth. Separate OAuth apps for develop and production |
| Cloudflare Turnstile (bot check for the demo login) | Cloudflare, global network, outside the EU | Only for visitors who click "Demo starten": the Turnstile script loads after the click and Cloudflare receives the IP address and browser signals to decide whether a person is there. Supabase Auth sends the resulting token (and, as Turnstile verification allows, the visitor's IP address) to Cloudflare for verification. GitHub-login visitors never reach Cloudflare. Accepted by Pascal on 2026-10-19 as an exception to EU residency (ADR 0012) |
| Sentry (error tracking, Functional Software, Inc.) | EU data region (Frankfurt): the SDK starts only for a DSN whose host is `o<id>.ingest.de.sentry.io` (checked in code, `lib/observability/sentry-options.ts`); the CSP allows exactly that host | Unexpected server and browser errors: error type and stack frame locations (file, function, line), release and environment; server events also runtime and OS name and version. No request, URL query or browser data; frame file names are the script files (normally `app:///_next/...`), and for inline code they can be the page path without query. An allowlist drops everything else before sending: exception messages, request bodies, headers, cookies, query strings, user, extra data, breadcrumbs. Only on errors: no sessions, tracing, client reports, replay or console capture, so a normal page view sends nothing. The browser connection reveals the visitor's IP address to Sentry; IP storage is turned off in the project settings (configuration, not checked in code). Retention 30 days (Developer plan). Off where no DSN is set (local, CI, previews). ADR 0022 |

Further processors are added with the PRs that introduce them.

Cloudflare DNS and Registrar for `sec-nblm.dev` are not processors of user data: the records point to Vercel and are not proxied, so Cloudflare sees DNS lookups (as any resolver chain does) but no app traffic (infra/cloudflare).

Websites fetched by the URL import (PR C2) are not processors: they receive a GET from Vercel's address with a generic User-Agent and no user data beyond the URL the user chose. The URL is never logged.

## Data

| Data | Where | Retention | On account deletion |
|---|---|---|---|
| Notebook memberships | `public.notebook_members` | While the membership exists | Deleted (foreign key cascade). Notebooks the user owns alone are deleted first, shared ones included; their members lose access and the dialog says so (ADR 0021) |
| Membership audit (who changed whose role, when) | `private.membership_audit`, no API access | 90 days: deleted daily by the pg_cron job `nblm-membership-audit-retention` (PR F1) | User ids (`user_id`, `actor`) are set to null for purged demo users (PR F1), and for every other deleted account within 15 minutes by the pg_cron job `nblm-forget-deleted-users` (ADR 0021). No foreign keys, so the audit outlives deleted notebooks |
| Sources (title, kind, object path, status, creator; for web pages the source URL, which may contain personal data in its query) | `public.sources` | Until the source or its notebook is deleted | Notebooks the user owns alone are deleted, files first (ADR 0021). `created_by` is set to null on sources in other notebooks; the source stays with the notebook |
| Chunks: source text and its embedding (personal data, AGENTS.md) | `public.chunks` | Until the source or its notebook is deleted (foreign key cascade) | As sources |
| Source files (uploaded PDFs, pasted text, fetched web page text) | Private Storage bucket `sources`, under `{notebook_id}/{source_id}` | Until the source is deleted (the server removes the file first, then the row, PR C1); leftovers become unreadable through the API once the source row is gone and are removed by the cleanup job (PR C4); C1 issues no signed download URLs, only signed upload URLs for one path, valid 2 hours per the Supabase docs (not measured). Such a URL still accepts an upload after its source was deleted (measured locally); that file is then reachable by no user and stays until the C4 sweep removes it | As sources |
| Chat messages (questions and answers) | `public.messages`, visible only to their author | Until the author deletes them, or the notebook or account is deleted | Deleted (foreign key cascade on `user_id`; the app deletes sole-owned notebooks first, so the last-owner guard does not block it, ADR 0021). A removed member's messages stay, invisible to everyone, until their account is deleted |
| Citations (cited chunk, quoted passage) | `public.message_citations`, visible only to the message's author | Until the message is deleted. When the cited source is deleted, the quote is emptied and the answer's text is replaced with "Antwort entfernt, Quelle gelöscht". Only answers with a citation to a deleted chunk are replaced: source text the model reproduced without citing it, or that a user pasted into a question, stays | As messages |
| Demo accounts (anonymous sign-in, block F) and everything they created: their copy of the demo notebook (sources and chunks with embeddings copied from the template, no files), messages and citations | `auth.users` (`is_anonymous`), `public.*` | Deleted within 24 h 15 min of sign-in by the pg_cron job `nblm-purge-demo-users` (every 15 minutes, PR F1) | Same job: notebooks, sources, chunks, messages, citations and memberships are deleted; audit and usage rows lose the user id |
| Model usage per operation (user, notebook, message, kind, model id, tokens, cost, latency, status; no prompt, source or answer text) | `private.usage`, no API access | 90 days with user, notebook and message ids; then the daily pg_cron job `nblm-usage-retention` (PR F1) sets all three to null, and cost, tokens, model, status and timing stay for aggregates | `user_id` is set to null (foreign key), the row and its cost stay for cost accounting. Same for `notebook_id` and `message_id` when those are deleted |

Remaining gap: database backups (configured in a later PR) keep deleted sources, chunks, quotes and answer texts until the backup's retention ends.
